LFM3 requires llama.cpp v0.8.0 (b11960) or later. Use the same supported build for the main guide and subsidiary examples.


Multimodal LFMs run on llama.cpp through its `mtmd` library. A vision or audio GGUF comes in two parts: the language model (`LFM3-VL-2B-QAD-Q4_0.gguf`) and a projector / encoder file (`mmproj-*.gguf`). `llama-server` and `llama-cli` load both; the same `mtmd` code is available in the iOS XCFramework and Android builds.

## Vision (LFM3-VL)

### Start the server

```bash
# -hf downloads the model and the matching mmproj automatically
llama-server -hf LiquidAI/LFM3-VL-2B-GGUF:Q4_0 -c 4096 --port 8080 --jinja --top-p 1.0 --min-p 0.0 --no-reasoning-preserve
```

Or with local files:

```bash
hf download LiquidAI/LFM3-VL-2B-GGUF LFM3-VL-2B-QAD-Q4_0.gguf mmproj-LFM3-VL-2B-Q8_0.gguf --local-dir .

llama-server -m LFM3-VL-2B-QAD-Q4_0.gguf --mmproj mmproj-LFM3-VL-2B-Q8_0.gguf \
  -c 4096 --port 8080 --jinja --top-p 1.0 --min-p 0.0 --no-reasoning-preserve -ngl 99
```

Useful flags: `--image-max-tokens` caps the number of image tokens per picture (lower = faster, coarser); `--no-mmproj-offload` keeps the vision encoder on CPU when GPU memory is tight.

### Send an image

Images travel as standard OpenAI `image_url` content parts — a `data:` URI with base64 bytes or a public URL.

```python
import base64
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8080/v1", api_key="not-needed")

with open("photo.jpg", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode()

response = client.chat.completions.create(
    model="LiquidAI/LFM3-VL-2B-GGUF:Q4_0",
    messages=[{
        "role": "user",
        "content": [
            {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{image_b64}"}},
            {"type": "text", "text": "Describe this image in two sentences."},
        ],
    }],
    temperature=0.1,
    max_tokens=2048,
    extra_body={"top_k": 50, "top_p": 1.0, "min_p": 0.0, "repeat_penalty": 1.1},
)
print(response.choices[0].message.content)
```

Multiple images in one message are supported; put each `image_url` part before the text that refers to it. Multi-turn works as for text — send the full history, and the image tokens stay in the prompt cache.

LFM3-VL can reason before answering, so leave a sufficient output budget. Its GGUF stores the recommended temperature, top-k, and repetition penalty. Use `--top-p 1.0 --min-p 0.0 --no-reasoning-preserve` on the server to apply the remaining settings and keep earlier reasoning out of history. See [Vision Capabilities](/lfm/key-concepts/vision-capabilities) and the [model page](/lfm/models/lfm3-vl-2b).

### Command line

```bash
llama-cli -m LFM3-VL-2B-QAD-Q4_0.gguf --mmproj mmproj-LFM3-VL-2B-Q8_0.gguf \
  --image photo.jpg -p "What is in this image?" \
  --temp 0.1 --top-k 50 --top-p 1.0 --min-p 0.0 --repeat-penalty 1.1
```

### In-process (mobile and embedded)

The `mtmd` C API sits next to `llama.h`: load the projector with `mtmd_init_from_file()`, tokenize a prompt that contains image markers plus the image bitmaps with `mtmd_tokenize()`, evaluate the chunks with `mtmd_helper_eval_chunks()`, then sample text with the usual `llama_sampler_sample()` loop. [`tools/mtmd/README-dev.md`](https://github.com/ggml-org/llama.cpp/blob/master/tools/mtmd/README-dev.md) documents the API and [`tools/mtmd/mtmd-cli.cpp`](https://github.com/ggml-org/llama.cpp/blob/master/tools/mtmd/mtmd-cli.cpp) is a compact reference. On Android build with `-DLLAMA_BUILD_MTMD=ON`; the iOS XCFramework already includes it.

Choose image resolution for the detail your task needs. Resizing can reduce latency and memory, but can also remove text or grounding detail; evaluate the tradeoff on your inputs.

## Audio and omni (LFM3)

LFM3-Audio and LFM3-Omni use llama.cpp's current multimodal path, with a language model and the matching projector. They do not use the older LFM2.5 dedicated audio runner and vocoder layout. Follow the [main Audio and Omni quickstart](/deployment/on-device/llama-cpp#audio-and-omni-models) for the complete ASR, server, and TTS commands.

For LFM3-Omni, follow the [model page](/lfm/models/lfm3-omni-2b#quick-start), including `--reasoning off`, video dependencies, and output controls. Server audio input uses OpenAI `input_audio` content parts; input formats and speech output endpoints differ from an image-only chat call.

## Older multimodal deployments

LFM2.5-VL still uses its own GGUF and projector with the same image request shape. Its sampling and image-token controls differ from LFM3; see the [model page](/lfm/models/lfm25-vl-1.6b).

The deprecated [LFM2.5-Audio model](/lfm/models/lfm25-audio-1.5b) retains its dedicated runner instructions for existing applications. Its four-file model/encoder/vocoder/speaker layout is not the LFM3 layout. Use [LFM3-Audio](/lfm/models/lfm3-audio-2b) for new speech applications.
