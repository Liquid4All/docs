[LiquidONNX](https://github.com/Liquid4All/onnx-export) is Liquid's export and inference toolkit. Start with LFM3 for a new text, vision, audio, or omni application. Use an older checkpoint when its size, specialization, or runtime support fits your deployment better.

<Note>
An ONNX file is not a complete runtime contract. LiquidONNX uses plain ONNX Runtime for LFM3 and ONNX Runtime GenAI for LFM2/LFM2.5. Its exports are not loadable by Transformers.js. Browser demos use their own compatible exports and inference code.
</Note>

## Install LiquidONNX

```bash
uv venv --python 3.12
source .venv/bin/activate
uv pip install --no-sources --no-config \
  "git+https://github.com/Liquid4All/onnx-export.git@26857c2e4d12381c6c630e7f7daf00bb3589f721" \
  "onnxruntime==1.30.0" "onnxruntime-genai==0.17.1" "transformers==5.23.0"
```

This CPU environment pins the LiquidONNX revision and stable runtime versions used for the text/VL checks. Run the commands outside an existing uv project so its dependencies do not replace this environment. The upstream development lock file can select nightly ONNX Runtime builds for other workloads, including MoE optimizations. CUDA requires a separate environment with the GPU distributions; follow the repository's [installation instructions](https://github.com/Liquid4All/onnx-export#2-installation).

## Model families

| Family | Runner | Export precisions |
| --- | --- | --- |
| LFM3 text | `lfm3-infer` | fp32, fp16, q4, q4f16, q4f32, q8, q8f16 |
| LFM3-VL | `lfm3-vl-infer` | fp32, fp16, q4, q4f16, q8, q8f16 |
| LFM3-Audio | `lfm3-audio-infer` | fp32, fp16, q4, q4f16, q8, q8f16 |
| LFM3-Omni | `lfm3-omni-infer` | fp32, fp16, q4, q4f16, q8, q8f16 |
| LFM2/LFM2.5 text | `lfm2-infer` | fp32, fp16, q4, q4f16, q4f32, q8 |
| LFM2/LFM2.5 VL | `lfm2-vl-infer` | fp32, fp16, q4, q8 |
| Supported LFM2/LFM2.5 MoEs | `lfm2-moe-infer` | fp32, fp16, q4, q4f16, q8 |
| LFM2.5-Audio | `lfm2-audio-infer` | fp32, fp16, q4, q8 |

The [upstream support table](https://github.com/Liquid4All/onnx-export#1-supported-models) lists supported checkpoints and decision models. Available files vary by exported repository; the table describes the exporter, not a guarantee that every precision has been published.

## LFM3 quickstart

Export the original checkpoint, not its MLX/GGUF or FP8/NVFP4 variant:

Exporting also writes FP32 intermediate weights. Budget memory and disk for those files, not only the final quantized model; CPU quantization can take several minutes. Use a compatible [pre-exported repository](#pre-exported-repositories) when you only need inference.

```bash
uv run --no-project lfm3-export LiquidAI/LFM3-1.7B --precision q4
uv run --no-project lfm3-infer --model exports/LFM3-1.7B-ONNX \
  --cpu --precision q4 --prompt "What is the capital of France?"
```

The model can reason before answering. Leave room for the reasoning in its token limit. The CLI's `--no-think` control changes the chat template; it does not make thinking-off quality equivalent to thinking-on quality.

For an image question:

```bash
uv run --no-project lfm3-vl-export LiquidAI/LFM3-VL-2B --precision q4
uv run --no-project lfm3-vl-infer --model exports/LFM3-VL-2B-ONNX \
  --cpu --precision q4 --images photo.jpg --prompt "Describe this image."
```

The VL CLI accepts images; graph support for video does not imply that this CLI accepts a video file. Likewise, the Omni CLI accepts text, images, and audio, with its own mode and output controls. Follow the upstream [Audio](https://github.com/Liquid4All/onnx-export#31d-lfm3-audio) and [Omni](https://github.com/Liquid4All/onnx-export#31e-lfm3-omni) recipes for ASR, TTS, and speech-to-speech.

## Older models

Older text checkpoints use a different runner and export format:

```bash
uv run --no-project lfm2-export LiquidAI/LFM2.5-1.2B-Instruct --precision q4
uv run --no-project lfm2-infer --model exports/LFM2.5-1.2B-Instruct-ONNX \
  --prompt "What is the capital of France?"
```

Use `lfm2-vl-export` / `lfm2-vl-infer` for older vision models, and the corresponding MoE or audio commands in the support table. Changing only the model ID in an `lfm2-*` command does not add LFM3 support.

## Pre-exported repositories

The [model matrix](/lfm/models/complete-library#complete-model-matrix) links each checkpoint's exact ONNX repository. Download the selected graph **and all of its external data files**, tokenizer/configuration files, and required encoders. Keep the graph and data files as real files in the same local export folder; ONNX Runtime can reject cache symlinks whose external data resolves outside the graph directory. Do not mix files from different revisions or precisions. Check that the repository was exported for the runner you intend to use; community exports can come from a different pipeline.

## Browser deployment

WebGPU support depends on the graph, precision, execution provider, and browser. Q4, Q8, and FP16 are not universal browser compatibility guarantees. For LFM3, follow LiquidONNX's [native ONNX Runtime Web guidance](https://github.com/Liquid4All/onnx-export#46-lfm3-families-on-webgpu), including the required operators, encoders, and cache handling.

The existing [vision browser demo](/examples/web/vl-webgpu-demo) and [audio browser demo](/examples/web/audio-webgpu-demo) retain their tested LFM2.5 models and export pipelines. Use them as scoped examples, rather than replacing their model IDs with LFM3. Use a browser with WebGPU enabled through its normal supported configuration; verify availability with `navigator.gpu`.
