Use vLLM for GPU serving, batching, and an OpenAI-compatible API. Start with [LFM3-1.7B](/lfm/models/lfm3-1.7b) for text or [LFM3-VL-2B](/lfm/models/lfm3-vl-2b) for images. The examples below use a CUDA GPU and vLLM 0.34.0, which adds native LFM3 support.

## Installation

Use an isolated Python 3.12 environment and a CUDA setup compatible with the [vLLM installation guide](https://docs.vllm.ai/en/latest/getting_started/installation/gpu/):

```bash
uv pip install "vllm==0.34.0" openai
```

LFM3 requires 0.34.0's native implementation. Follow the [release notes](https://github.com/vllm-project/vllm/releases/tag/v0.34.0) when upgrading an existing deployment; defaults and dependencies changed too.

## Serve LFM3 text

```bash
vllm serve LiquidAI/LFM3-1.7B \
  --trust-remote-code \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice --tool-call-parser qwen3_coder \
  --max-model-len 4096 --gpu-memory-utilization 0.8 --enforce-eager
```

Review the checkpoint's configuration code before enabling `--trust-remote-code`. `--enforce-eager` uses eager execution for this quickstart rather than CUDA graph capture. The 4,096-token limit is a small quickstart budget, not the checkpoint's maximum context. Increase it to fit your task and GPU memory.

Install the client with `uv pip install openai`, then send a request:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
response = client.chat.completions.create(
    model="LiquidAI/LFM3-1.7B",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
    temperature=0.1,
    max_tokens=2048,
    extra_body={"top_k": 50, "repetition_penalty": 1.1},
)
print(response.choices[0].message.content)
```

Leave room for reasoning as well as the final answer. The reasoning parser separates reasoning from `content`; it does not disable thinking. See [Thinking](/lfm/key-concepts/thinking). Set `stream=True` for streaming responses, and pass OpenAI-style `tools` for parsed tool calls. Use `response_format` with a JSON schema for constrained JSON output.

## Vision, audio, and omni

For images, use the launch configuration on the [LFM3-VL model page](/lfm/models/lfm3-vl-2b#quick-start), then send OpenAI `image_url` content parts. Multimodal input limits and memory needs differ from text-only serving.

Upstream vLLM lists additional [LFM3 multimodal architectures](https://docs.vllm.ai/en/latest/models/supported_models/). Architecture registration alone does not establish speech output, video handling, or a particular API contract. Follow a tested example for the exact checkpoint and modality; the [Audio](/lfm/models/lfm3-audio-2b) and [Omni](/lfm/models/lfm3-omni-2b) pages retain their documented runtime paths.

## LFM2.5 and LFM2

Older supported checkpoints keep their native architectures and tool-call formats:

```bash
vllm serve LiquidAI/LFM2.5-1.2B-Instruct \
  --enable-auto-tool-choice --tool-call-parser lfm2 \
  --max-model-len 4096 --gpu-memory-utilization 0.8 --enforce-eager
```

The client request has the same shape. Change `model` to match the server and use that checkpoint's sampling settings. For LFM2.5-1.2B-Instruct, use `temperature=0.1`, `top_k=50`, and `repetition_penalty=1.05`. Original LFM2 models and thinking/MoE variants have their own settings; check the model's quickstart rather than inheriting LFM3's parser or generation preset.
