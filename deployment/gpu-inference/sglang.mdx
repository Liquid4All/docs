Use SGLang for CUDA GPU serving with an OpenAI-compatible API. Start with [LFM3-1.7B](/lfm/models/lfm3-1.7b) for text or [LFM3-VL-2B](/lfm/models/lfm3-vl-2b) for images.

## Installation

Build an image from the official `v0.5.23-cu130` CUDA container with the [LFM3 integration](https://github.com/sgl-project/sglang/pull/46858). This pins both the source revision and its required Transformers version while retaining the image's CUDA/compiler packages. SGLang 0.5.23 alone did not run the LFM3 examples correctly.

On a Linux host with an NVIDIA GPU and the NVIDIA Container Toolkit:

```dockerfile
# Dockerfile.sglang
FROM lmsysorg/sglang@sha256:f832b5c39559c9caa900b22ad37c76fcce66470676855c42052102c537812f1f
ENV SGLANG_BUILD_RUST_EXTS=none
RUN python3 -m pip install \
    "sglang @ git+https://github.com/sgl-project/sglang.git@47361c57be9fcc23f11b9804633bfcfe9342f98e#subdirectory=python" \
    && python3 -m pip install "transformers==5.19.0"
ENTRYPOINT ["sglang", "serve"]
```

```bash
docker build -f Dockerfile.sglang -t lfm-sglang .
```

A clean pip install can select incompatible CUDA compiler/header packages or lack the library layout required by JIT kernels. For a source installation, follow the [upstream CUDA prerequisites](https://docs.sglang.ai/get_started/install.html) rather than assuming the container's environment exists on the host. The direct Transformers inference guide uses a separate environment and a newer Transformers version.

## Serve LFM3 text

```bash
docker run --rm --gpus all --ipc=host -p 30000:30000 lfm-sglang \
  --model-path LiquidAI/LFM3-1.7B \
  --trust-remote-code --reasoning-parser qwen3 \
  --tool-call-parser qwen3_coder \
  --context-length 4096 --mem-fraction-static 0.8 \
  --host 0.0.0.0 --port 30000
```

Review the checkpoint's code before enabling `--trust-remote-code`. The context limit is a quickstart memory budget, not the checkpoint's maximum. Leave room for reasoning and the final answer.

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:30000/v1", api_key="EMPTY")
response = client.chat.completions.create(
    model="LiquidAI/LFM3-1.7B",
    messages=[{"role": "user", "content": "What is the capital of France?"}],
    temperature=0.1,
    max_tokens=2048,
    extra_body={"top_k": 50, "repetition_penalty": 1.1},
)
print(response.choices[0].message.content)
```

The parser separates reasoning from the final `content`; it does not turn thinking off. Follow [Thinking](/lfm/key-concepts/thinking) for supported controls and limitations. Pass `stream=True` for streaming, OpenAI-style `tools` for tool calls, and `response_format` with a JSON schema for constrained output.

## Vision and omni

LFM3-VL uses the checkpoint's `auto` response/tool parsers and additional launch flags. Use the complete [model-page command](/lfm/models/lfm3-vl-2b#quick-start), then send OpenAI `image_url` content parts. A text-only launch command is not the complete vision configuration.

[LFM3-Omni](/lfm/models/lfm3-omni-2b#quick-start) has its own input/output contract. Use its documented modality-specific path; do not infer speech-generation support from a text endpoint.

## LFM2.5 and LFM2

Inside the same configured container, older text models use the `lfm2` tool parser and their own sampling settings:

```bash
docker run --rm --gpus all --ipc=host -p 30000:30000 lfm-sglang \
  --model-path LiquidAI/LFM2.5-1.2B-Instruct \
  --tool-call-parser lfm2 \
  --context-length 4096 --mem-fraction-static 0.8 \
  --host 0.0.0.0 --port 30000
```

The client request has the same shape. Change `model` to match the server; LFM2.5-1.2B-Instruct uses `temperature=0.1`, `top_k=50`, and `repetition_penalty=1.05`. Thinking variants need their model-specific reasoning parser. Original LFM2 checkpoints and MoEs also have their own settings.

## Speculative decoding

DSpark applies only to checkpoints with a published compatible drafter. It is not enabled by changing an LFM2.5 target to LFM3. Follow [Speculative Decoding](/lfm/key-concepts/speculative-decoding) and the selected model's quickstart for the target/drafter pair and required SGLang build.
