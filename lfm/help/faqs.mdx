## General Questions

<Accordion title="What are LFM models?">
LFM (Liquid Foundation Models) are Liquid AI's efficient models for local and hosted deployment. [LFM3](/lfm/models/complete-library) is the latest generation, with text, vision, audio, omni, and decision models. The library also includes smaller and specialized LFM2.5 and LFM2 models, including embedding and encoder models. Open-weight models range from 230M to 24B parameters.
</Accordion>

<Accordion title="What context length do LFM models support?">
[LFM3-1.7B](/lfm/models/lfm3-1.7b) supports 256K tokens, and [LFM3-VL-2B](/lfm/models/lfm3-vl-2b) supports 128K. Other limits vary by model: many LFM text, vision, and audio models support 32K, [LFM2.5-8B-A1B](/lfm/models/lfm25-8b-a1b) supports 128K, and [LFM2.5-24B-A2B](/lfm/models/lfm25-24b-a2b) supports 131K. Encoder-based models have shorter limits (8K for the LFM2.5 encoders, 16K for d1-omni-600M). Each model page lists its exact limit; hosted API limits can differ from the open-weight checkpoints.
</Accordion>

<Accordion title="Which inference frameworks are supported?">
LFM models are compatible with the frameworks below. Support varies by model (for example, audio and decision models run on fewer frameworks), so check each model page.
- [Transformers](/deployment/gpu-inference/transformers) - For research and development
- [llama.cpp](/deployment/on-device/llama-cpp) - For efficient CPU inference, including [iOS and Android apps](/deployment/on-device/llama-cpp/mobile)
- [vLLM](/deployment/gpu-inference/vllm) - For high-throughput production serving
- [zml/llmd](/deployment/gpu-inference/zml-llmd) - For high-throughput and fast startup
- [MLX](/deployment/on-device/mlx) - For Apple Silicon optimization
- [Ollama](/deployment/on-device/ollama) - For easy local deployment
</Accordion>

## Model Selection

<Accordion title="Which model should I use for my use case?">
- **General chat/instruction following**: [LFM3-1.7B](/lfm/models/lfm3-1.7b)
- **Vision tasks**: [LFM3-VL-2B](/lfm/models/lfm3-vl-2b)
- **Audio/speech**: [LFM3-Audio-2B](/lfm/models/lfm3-audio-2b)
- **Combined vision and audio**: [LFM3-Omni-2B](/lfm/models/lfm3-omni-2b)
- **Extraction from text**: [LFM3-1.7B](/lfm/models/lfm3-1.7b) with structured output
- **Classification, routing, and scoring**: [decision models](/lfm/models/decision-models) such as [d1-2B](/lfm/models/d1-2b)
- **Specialized extraction from images**: [LFM2.5-VL-1.6B-Extract](/lfm/models/lfm25-vl-1.6b-extract) or [LFM2.5-VL-450M-Extract](/lfm/models/lfm25-vl-450m-extract)
- **Smallest footprint**: [LFM2.5-230M](/lfm/models/lfm25-230m) or [LFM2.5-350M](/lfm/models/lfm25-350m) for tight memory budgets
- **Larger reasoning model**: [LFM2.5-24B-A2B](/lfm/models/lfm25-24b-a2b) (MoE architecture, 131K context); evaluate it on your task when a larger model fits your hardware
</Accordion>

<Accordion title="What is the difference between LFM versions?">
- **LFM3** is the latest generation. Its tri-hybrid architecture combines gated short convolutions, sliding-window attention, and global attention. The family includes text, vision, audio, omni, and decision models, with updated chat templates and tool-call formats.
- **LFM2.5** builds on the LFM2 architecture with improved training. Some models extend the context window or vocabulary. It remains useful for smaller footprints, larger MoE models, and specialized tasks.
- **LFM2** is the earlier generation. Some specialized models remain useful; deprecated models and their replacements are listed on the [Deprecations](/lfm/help/deprecations) page.

Start with LFM3 for general use, then consider an older model when its size, specialization, or runtime support better fits your needs. Use the selected model's own [chat template](/lfm/key-concepts/chat-template), [tool-call format](/lfm/key-concepts/tool-use), and generation settings.
</Accordion>

<Accordion title="What are Liquid Nanos?">
[Liquid Nanos](/lfm/models/liquid-nanos) are task-specific models fine-tuned for specialized use cases like:
- Structured extraction from images (LFM2.5-VL-1.6B-Extract, LFM2.5-VL-450M-Extract)
- Retrieval for RAG pipelines (LFM2.5-Embedding-350M, LFM2.5-ColBERT-350M)
- Translation (LFM2-350M-ENJP-MT)
- Meeting summarization (LFM2-2.6B-Transcript)
</Accordion>

## Deployment

<Accordion title="Can I run LFM models on mobile devices?">
Yes! llama.cpp runs natively on iOS and Android with quantized GGUF models. See [iOS & Android](/deployment/on-device/llama-cpp/mobile) for embedding it in an app, and [Vision & Audio](/deployment/on-device/llama-cpp/multimodal) for multimodal models.
</Accordion>

<Accordion title="What quantization formats are available?">
- **GGUF**: For llama.cpp, LM Studio, Ollama, Atomic Chat (Q4_0, Q4_K_M, Q5_K_M, Q6_K, Q8_0, BF16, F16; some repositories ship a subset)
- **MLX**: For Apple Silicon (4-bit, 5-bit, 6-bit, 8-bit, bf16)
- **ONNX**: For cross-platform deployment with ONNX Runtime
</Accordion>

<Accordion title="How do I choose the right quantization level?">
- **Q4_0 / 4-bit**: Smallest size, fastest inference, some quality loss
- **Q8_0 / 8-bit**: Good balance of size and quality
- **F16 / bf16**: Full precision, best quality, largest size

For most use cases, Q4_K_M or Q5_K_M provide good quality with significant size reduction.
</Accordion>

## Fine-tuning

<Accordion title="Can I fine-tune LFM models?">
Yes. Most open-weight LFM models support fine-tuning with [TRL](/lfm/fine-tuning/trl) and [Unsloth](/lfm/fine-tuning/unsloth), MoE models can be trained across GPUs with [Halo](/lfm/fine-tuning/halo), and audio models use the [liquid-audio](https://github.com/Liquid4All/liquid-audio#finetuning) trainer. Check the [Model Library](/lfm/models/complete-library) for trainability information.
</Accordion>

<Accordion title="What fine-tuning methods are supported?">
- **LoRA/QLoRA**: Memory-efficient fine-tuning
- **Full fine-tuning**: For maximum customization
- **SFT (Supervised Fine-Tuning)**: For instruction tuning
</Accordion>
