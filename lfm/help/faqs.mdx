## General Questions

<Accordion title="What are LFM models?">
LFM (Liquid Foundation Models) are a family of efficient models built on a new hybrid architecture designed for fast training and inference. Open-weight models range from 230M to 24B parameters ([LFM2.5-24B-A2B](/lfm/models/lfm25-24b-a2b) is the largest) and support text, vision, and audio. The family also includes embedding, encoder, and [decision models](/lfm/models/decision-models).
</Accordion>

<Accordion title="What context length do LFM models support?">
Most LFM text, vision, and audio models support a 32K token context length. [LFM2.5-8B-A1B](/lfm/models/lfm25-8b-a1b) supports 128K tokens, and [LFM2.5-2.6B](/lfm/models/lfm25-2.6b) and [LFM2.5-24B-A2B](/lfm/models/lfm25-24b-a2b) support 131K. Encoder-based models have shorter limits (8K for the LFM2.5 encoders, 16K for d1-omni-600M). Each model page lists its exact limit.
</Accordion>

<Accordion title="Which inference frameworks are supported?">
LFM models are compatible with the frameworks below. Support varies by model (for example, audio and decision models run on fewer frameworks), so check each model page.
- [Transformers](/deployment/gpu-inference/transformers) - For research and development
- [llama.cpp](/deployment/on-device/llama-cpp) - For efficient CPU inference, including [iOS and Android apps](/deployment/on-device/llama-cpp/mobile)
- [vLLM](/deployment/gpu-inference/vllm) - For high-throughput production serving
- [MLX](/deployment/on-device/mlx) - For Apple Silicon optimization
- [Ollama](/deployment/on-device/ollama) - For easy local deployment
</Accordion>

## Model Selection

<Accordion title="Which model should I use for my use case?">
- **General chat/instruction following**: LFM2.5-1.2B-Instruct (recommended)
- **Vision tasks**: LFM2.5-VL-1.6B
- **Audio/speech**: LFM2.5-Audio-1.5B
- **Extraction from images**: LFM2.5-VL-1.6B-Extract or LFM2.5-VL-450M-Extract
- **Extraction from text**: LFM2.5-1.2B-Instruct, LFM2.5-350M, or LFM2.5-230M
- **Classification, routing, and scoring**: [decision models](/lfm/models/decision-models) such as d1-3B
- **Edge deployment**: LFM2.5-230M or LFM2.5-350M for the smallest footprint
- **Highest performance**: LFM2.5-24B-A2B (MoE architecture, 131K context)
</Accordion>

<Accordion title="What is the difference between LFM2 and LFM2.5?">
LFM2.5 models are updated versions with improved training that deliver higher performance on the same hybrid architecture. Some LFM2.5 models also extend the context window or vocabulary. We recommend using LFM2.5 variants when available.
</Accordion>

<Accordion title="What are Liquid Nanos?">
[Liquid Nanos](/lfm/models/liquid-nanos) are task-specific models fine-tuned for specialized use cases like:
- Structured extraction from images (LFM2.5-VL-1.6B-Extract, LFM2.5-VL-450M-Extract)
- Retrieval for RAG pipelines (LFM2.5-Embedding-350M, LFM2.5-ColBERT-350M)
- Translation (LFM2-350M-ENJP-MT)
- Meeting summarization (LFM2-2.6B-Transcript)
</Accordion>

## Deployment

<Accordion title="Can I run LFM models on mobile devices?">
Yes! llama.cpp runs natively on iOS and Android with quantized GGUF models. See [iOS & Android](/deployment/on-device/llama-cpp/mobile) for embedding it in an app, and [Vision & Audio](/deployment/on-device/llama-cpp/multimodal) for multimodal models.
</Accordion>

<Accordion title="What quantization formats are available?">
- **GGUF**: For llama.cpp, LM Studio, Ollama, Atomic Chat (Q4_0, Q4_K_M, Q5_K_M, Q6_K, Q8_0, BF16, F16; some repositories ship a subset)
- **MLX**: For Apple Silicon (4-bit, 5-bit, 6-bit, 8-bit, bf16)
- **ONNX**: For cross-platform deployment with ONNX Runtime
</Accordion>

<Accordion title="How do I choose the right quantization level?">
- **Q4_0 / 4-bit**: Smallest size, fastest inference, some quality loss
- **Q8_0 / 8-bit**: Good balance of size and quality
- **F16 / bf16**: Full precision, best quality, largest size

For most use cases, Q4_K_M or Q5_K_M provide good quality with significant size reduction.
</Accordion>

## Fine-tuning

<Accordion title="Can I fine-tune LFM models?">
Yes. Most open-weight LFM models support fine-tuning with [TRL](/lfm/fine-tuning/trl) and [Unsloth](/lfm/fine-tuning/unsloth); audio models use the [liquid-audio](https://github.com/Liquid4All/liquid-audio#finetuning) trainer. Check the [Model Library](/lfm/models/complete-library) for trainability information.
</Accordion>

<Accordion title="What fine-tuning methods are supported?">
- **LoRA/QLoRA**: Memory-efficient fine-tuning
- **Full fine-tuning**: For maximum customization
- **SFT (Supervised Fine-Tuning)**: For instruction tuning
</Accordion>
