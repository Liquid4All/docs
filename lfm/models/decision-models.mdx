Decision models are a new class of AI model purpose-built for structured decisions. Instead of generating text token by token, a decision model evaluates a situation and returns calibrated probabilities across a fixed set of outcomes in a single call with zero generated tokens.

## Which d1 Should I Use?

| Model | Access | Inputs | Use it when |
|---|---|---|---|
| [d1-ultra](/lfm/models/d1#models) | Liquid API, OpenRouter, Vercel AI Gateway | Text, images | You need the most capable decision model, for harder decisions. |
| [d1.1](/lfm/models/d1) | Liquid API | Text, images | You want a hosted model at a lower price than d1-ultra. |
| [d1-2B](/lfm/models/d1-2b) | Open weights (1.9B) | Text, images, video | You want to run locally or on your own hardware, or need typed answers (values, boxes, estimates). |
| [d1-omni-2B](/lfm/models/d1-omni-2b) | Open weights (2.2B) | Text, images, video, audio | Your inputs include audio, such as calls, voice messages, or spoken questions. |
| [d1-omni-600M](/lfm/models/d1-omni-600m) | Open weights (587M) | Text with images or audio | You need the smallest model, or audio input (up to 30 s of speech). |

## Pricing

The hosted models are billed on input tokens only. Output is free because decision models do not generate tokens. Each question is billed as its own prompt, including its text and all images. See [Image Token Usage](/lfm/models/d1#image-token-usage) for how images are counted.

The models are available through the [Liquid Console](https://console.liquid.ai). d1-ultra and the earlier d1 model are also on [OpenRouter](https://openrouter.ai/liquid/d1) and [Vercel AI Gateway](https://vercel.com/ai-gateway/models/d1). See the [Liquid AI pricing page](https://www.liquid.ai/pricing) for current prices and available credits.

d1-2B, d1-omni-2B, and d1-omni-600M are open-weight models under the [LFM Open License](/lfm/help/model-license) and free to run on your own hardware.

## Primitives

Every question you ask a decision model uses one of three core types:

| If the answer is... | Use | Example |
|---|---|---|
| Pick one from a set of unordered categories | **Choice** | Which department handles this ticket? |
| Rate something along an ordered scale with defined levels | **Score** | How severe is this bug? |
| Yes or no, where the probability itself is useful | **Noul** | Does this message contain personal data? |

- **Noul**: A yes/no question that returns a probability between 0 and 1. "Is this message spam?" might return `0.92`.
- **Choice**: A pick-one-from-many question that returns a probability distribution over named options.
- **Score**: A rate-on-a-scale question that returns a probability-weighted position on an ordered rubric.

### Typed Answers

[d1-2B](/lfm/models/d1-2b) and [d1-omni-2B](/lfm/models/d1-omni-2b) add typed answers on top of the three core types:

| Type | Question | Answer |
|---|---|---|
| `choice` with `multiple: true` | Any of the options `criteria` names | `choices`, with each option's own probability |
| `text`, `number`, `date` | A value to read from the state | The value (a number with its unit, a date in ISO 8601), its `span`, and `found` |
| `number` with `range` | An estimate, `step` apart | The median `number` and an `interval` (p10, p90) |
| `box`, `boxes` | One object, or every instance (16 at most, or `max`), in the picture | `box` (top, bottom, left, right as fractions of the picture), or `boxes` and `count` |

A value or a box is missing when `found` is under 0.5, and it is then `None`.

## When to Use Decision Models

Decision models are a good fit when the answer is a structured decision: classification, categorization, routing (tickets, emails, requests), scoring, triage, content moderation, guardrails and safety checks, LLM-as-judge replacement, agent tool-call approval, and model routing or cascades.

With image input, the same primitives support visual inspection, image classification, and decisions based on screenshots. With audio (d1-omni-2B and d1-omni-600M), they support voice-command routing and spoken-intent detection.

Use a language model instead for free-form text generation, creative writing, multi-turn conversation, complex multi-step reasoning, open-ended Q&A, summarization, and code generation.

To move existing LLM calls to a decision model, see the [Decision Model Guide](/guides/decision-model-guide).
