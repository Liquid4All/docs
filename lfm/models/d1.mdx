d1.2 and d1.2-ultra are hosted decision models on the Liquid API. They take text, images, and audio, and return calibrated answers with zero generated tokens.

Besides Noul, Choice, and Score questions, they answer five new tasks:

- **Read a value** (`text`, `number`, `date`): a value from the input, with the characters it was read from, or "not found".
- **Find every passage** (`spans`): every passage of a kind in a text, such as each piece of personal data.
- **Locate objects** (`box`, `boxes`): a box around one object in a picture, or around every instance with a count.
- **Estimate a number** (`number` with a `range`): a best guess with a likely range, such as the number of people in a photo.
- **Pick several options** (`choice` with `multiple`): every option that applies, each with its own probability.

For an overview of decision model primitives and when to use them, see [Decision Models](/lfm/models/decision-models).

## Models

Pick the hosted model with the `model` field. Both models use the same endpoint, question types, and response format.

| Model | Inputs | Input price (per 1M tokens) | Input limit per question | Description |
| ----- | ----- | ----- | ----- | ----- |
| `d1.2-ultra` | Text, images, audio | $0.042 | 65,536 tokens | Most capable decision model, for harder decisions. |
| `d1.2` | Text, images, audio | $0.02 | 65,536 tokens | Default hosted decision model. Faster, at less than half the price. |

The examples below use `d1.2`. Replace it with `d1.2-ultra` for harder decisions.

<Note>
`d1.1`, `d1-ultra`, and the earlier `d1` are deprecated. They still answer Noul, Choice, and Score questions, but not the new tasks or audio. To migrate, change `model` to `d1.2` (from `d1` or `d1.1`) or `d1.2-ultra` (from `d1-ultra`). The request and response format is unchanged. See [Deprecations](/lfm/help/deprecations#deprecated-api-models).
</Note>

## Your First Call

A single API call contains the following fields:

1. **Model**: which decision model to use.
2. **State**: the context the model should evaluate. This can be plain text (a customer message, an email, a log entry) or a JSON object with structured fields.
3. **Questions**: up to 128 questions, each with a name, a type, and instructions. Choice and Score questions also take criteria that define the options or levels. The model evaluates all the questions of a call at once.
4. **Images** (optional): images to evaluate alongside the state, in the top-level `images` array. See [Image Inputs](#image-inputs).
5. **Audio** (optional): audio clips to evaluate alongside the state, in the top-level `media` array. See [Audio Inputs](#audio-inputs).

<Tabs>
  <Tab title="cURL">
    ```bash
    curl -s https://api.liquid.ai/decisions/v1/systemone \
      -H "Authorization: Bearer $LIQUID_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "model": "d1.2",
        "state": "I have been waiting over three weeks for my order and nobody has responded to my emails. This is completely unacceptable.",
        "questions": {
          "is_complaint": {
            "type": "noul",
            "instructions": "Is this message a complaint from the customer?"
          }
        }
      }'
    ```
  </Tab>
  <Tab title="Python">
    ```python
    from typesafe_sdk import Noul
    
    result = client.system_one(
        model="d1.2",
        state="I have been waiting over three weeks for my order and nobody has responded to my emails. This is completely unacceptable.",
        questions={
            "is_complaint": Noul(
                instructions="Is this message a complaint from the customer?",
            ),
        },
    )
    print(result.answers["is_complaint"].noul)  # 0.989
    ```
  </Tab>
  <Tab title="TypeScript">
    ```typescript

      model: "d1.2",
      state: "I have been waiting over three weeks for my order and nobody has responded to my emails. This is completely unacceptable.",

          type: "noul",
          instructions: "Is this message a complaint from the customer?",
        },
      },
    });
    console.log(result.answers.is_complaint.noul); // 0.989
    ```
  </Tab>
</Tabs>

**Response:**

```json
{
  "model": "d1.2",
  "answers": {
    "is_complaint": {
      "type": "noul",
      "noul": 0.989
    }
  },
  "usage": {
    "input_tokens": 54,
    "output_tokens": 0
  }
}
```

**Reading the response:**

- **`answers.is_complaint.noul`**: The probability that the answer is "yes." Here, `0.989` means a 0.989 probability that this is a complaint.
- **`usage.output_tokens`**: Always `0`. Decision models do not generate tokens.
- **`usage.input_tokens`**: The input tokens billed for the request: the state, images, and audio once, plus the text of each question.

The response contains one answer per question, keyed by the question name. A Noul answer is a single probability. Choice and Score answers also include a full probability distribution and a `confidence` value. [Typed answers](#typed-answers) have their own fields.

## Usage Examples

### Noul

A Noul question returns a single probability between 0 and 1. Your code receives a float that you can threshold to make a binary decision, use as a weight, or pass directly to downstream logic. Values near 0 or 1 express a clear answer; values near 0.5 express genuine uncertainty.

    ```bash
        "questions": {
          "is_harmful": {
            "type": "noul",
    ```

### Choice

A Choice question returns the selected option, a probability distribution over all options, and a `confidence` value. `confidence` summarizes how clear-cut the answer is: high when one option clearly wins, lower when the probability is spread across several options. The distribution tells you not just the top pick but how much probability mass sits on the runner-up, which is useful for flagging ambiguous cases or routing to a fallback.

### Score

A Score question returns a continuous value across an ordered rubric you define, plus the probability distribution over each level. The value is the probability-weighted position on the scale: if you define four levels (0 through 3), a score of `2.994` means the model places nearly all weight on the top level.

## Typed Answers

d1.2 and d1.2-ultra answer five more tasks with the same endpoint and request format. Every question has a `type` and `instructions`, and every answer repeats its `type`. Earlier models return `422` on these questions.

| Task | Question | Question fields | Answer fields |
| ----- | ----- | ----- | ----- |
| Read a value | `text`, `number`, `date` | `unit` (optional, `number` only) | The value (`text`, `number` with its `unit`, or `date` in ISO 8601), `text` (as written), `span`, `found` |
| Find every passage | `spans` | `max` (optional): the most passages to read, 1 to 64 (16 by default) | `spans` (each with `text`, `span`, `found`), `count`, `at_least`, `presence` |
| Locate objects | `box`, `boxes` | `boxes` only: `max` (optional), 1 to 64 (16 by default) | `box` (`top`, `bottom`, `left`, `right` as fractions of the picture), `found`, `confidence`. For `boxes`: `boxes`, `count`, `at_least`, `presence` |
| Estimate a number | `number` with `range` | `range`: `[low, high]`. `step` (optional): the spacing of the values, which must divide `high - low`. `unit` (optional) | `number` (the median), `interval` (`[p10, p90]`), `unit` |
| Pick several options | `choice` with `"multiple": true` | `criteria`: the options, as `{name: description}` | `choices` (the options with a probability of at least 0.5), `probabilities` (each option's own probability) |

The TypeSafe SDKs don't send these question types yet, so the examples below call the endpoint directly.

### Read a Value

A `text`, `number`, or `date` question reads one value from the state and returns it with the characters it came from. `span` holds the start and end positions of those characters in the state. When the value isn't in the state, `found` is low and the value is `null`, so the model says "not found" instead of guessing.

<Tabs>

    ```bash
    curl -s https://api.liquid.ai/decisions/v1/systemone \

      -H "Content-Type: application/json" \
      -d '{
        "model": "d1.2",
        "state": "ACME SA\nInvoice 2026-117\nTotal due: 1 234,50 EUR\nPay before 03/04/2026 (day/month/year)",

          "payee": {"type": "text", "instructions": "Who issued the invoice?"},
          "total": {"type": "number", "instructions": "How much is due?"},
          "due": {"type": "date", "instructions": "By when must it be paid?"},
          "vat": {"type": "number", "instructions": "How much VAT is charged?"}
        }
      }'
    ```
  </Tab>

### Find Every Passage

A `spans` question returns every passage of a kind in the state, each with its text and position. Use it for redaction, for example to find every piece of personal data before a note is stored.

```python
response = requests.post(
    "https://api.liquid.ai/decisions/v1/systemone",
    headers={"Authorization": f"Bearer {os.environ['LIQUID_API_KEY']}"},
    json={
        "model": "d1.2",
        "state": "Patient Rachel Kim (DOB 1984-02-11) called from 415-555-0142 about her refill. Email: rkim@example.com.",
        "questions": {
            "pii": {"type": "spans", "instructions": "Every piece of personal data."},
        },
    },
)
for span in response.json()["answers"]["pii"]["spans"]:
    print(span["text"], span["span"])
```

**Response** (`answers` field, `presence` shortened):

```json
{
  "pii": {
    "type": "spans",
    "spans": [
      {"text": "Rachel Kim", "span": [8, 18], "found": 0.997},
      {"text": "1984-02-11", "span": [24, 34], "found": 0.953},
      {"text": "415-555-0142", "span": [48, 60], "found": 0.926},
      {"text": "rkim@example.com", "span": [86, 102], "found": 0.813}
    ],
    "count": 4,
    "at_least": false,
    "presence": [0.997, 0.953, 0.926, 0.813, "..."]
  }
}
```

The model reads up to `max` passages (16 by default). `presence` holds the probability of each of these slots, in order, and `spans` keeps those of at least 0.5. `at_least` is `true` when every slot was used, so the state may hold more passages than `count`: raise `max` to read them.

### Pick Several Options

A `choice` question with `"multiple": true` answers each option yes or no on its own. `choices` lists every option with a probability of at least 0.5.

```python
response = requests.post(
    "https://api.liquid.ai/decisions/v1/systemone",
    headers={"Authorization": f"Bearer {os.environ['LIQUID_API_KEY']}"},
    json={
        "model": "d1.2",
        "state": "My package arrived late and I was charged twice for it.",
        "questions": {
            "topics": {
                "type": "choice",
                "multiple": True,
                "instructions": "Which topics does the message raise?",
                "criteria": {
                    "billing": "Charges and payments",
                    "delivery": "Shipping and arrival",
                    "product": "Product quality",
                    "account": "Login and profile",
                },
            },
        },
    },
)
```

**Response** (`answers` field):

```json
{
  "topics": {
    "type": "choice",
    "choices": ["billing", "delivery"],
    "probabilities": {"billing": 0.968, "delivery": 0.969, "product": 0.0024, "account": 0.0007}
  }
}
```

The probabilities don't sum to 1, since each option is its own yes-or-no question.

### Estimate a Number

A `number` question with a `range` estimates a quantity instead of reading it. The model returns its median estimate and an interval from the 10th to the 90th percentile. It reads at most 128 values between `low` and `high`, `step` apart. Estimates are reliable on counts and scores, less so on free quantities. They have no `found`.

```python
import base64
from pathlib import Path

image = base64.b64encode(Path("photo.jpg").read_bytes()).decode("ascii")

response = requests.post(
    "https://api.liquid.ai/decisions/v1/systemone",
    headers={"Authorization": f"Bearer {os.environ['LIQUID_API_KEY']}"},
    json={
        "model": "d1.2",
        "state": "A group photograph.",
        "images": [f"data:image/jpeg;base64,{image}"],
        "questions": {
            "people": {
                "type": "number",
                "instructions": "How many people are in the photo?",
                "range": [0, 60],
                "step": 1,
            },
        },
    },
)
```

**Response** (`answers` field):

```json
{
  "people": {"type": "number", "number": 26, "interval": [23, 30], "unit": null}
}
```

### Locate Objects

A `box` question returns a box around one object in a picture. A `boxes` question returns a box around every instance, in reading order, with a count. Box edges are fractions of the picture's height (`top`, `bottom`) and width (`left`, `right`), from its top-left corner. A request with a `box` or `boxes` question must have exactly one image.

```python
response = requests.post(
    "https://api.liquid.ai/decisions/v1/systemone",
    headers={"Authorization": f"Bearer {os.environ['LIQUID_API_KEY']}"},
    json={
        "model": "d1.2-ultra",
        "state": "A group photograph.",
        "images": [f"data:image/jpeg;base64,{image}"],
        "questions": {
            "glasses": {"type": "box", "instructions": "The person wearing round glasses."},
            "faces": {"type": "boxes", "instructions": "Every face.", "max": 4},
        },
    },
)
```

**Response** (`answers` field, shortened):

```json
{
  "glasses": {
    "type": "box",
    "box": {"top": 0.378, "bottom": 0.522, "left": 0.212, "right": 0.296},
    "found": 0.939,
    "confidence": 0.738
  },
  "faces": {
    "type": "boxes",
    "boxes": [
      {"box": {"top": 0.478, "bottom": 0.521, "left": 0.046, "right": 0.078}, "found": 1, "confidence": 0.567},
      {"box": {"top": 0.519, "bottom": 0.575, "left": 0.072, "right": 0.103}, "found": 1, "confidence": 0.427},
      "..."
    ],
    "count": 4,
    "at_least": true,
    "presence": [1, 1, 0.998, 0.997]
  }
}
```

`found` is the probability that the object is in the picture, and `confidence` how sure the model is of the box itself. A box is missing when `found` is under 0.5, and `box` is then `null`. Here `at_least` is `true` because all four slots of `max` were used: the photo holds more faces.

### Typed Answer Tips

- **Read from text:** reads and spans point into the text of the state. A value that only appears in an image is not found, so send the document's text (from a PDF's text layer or from OCR) as the state.
- **Positions:** `span` counts Unicode code points of the state, end excluded. When the state is JSON, positions count the state as rendered with 2-space indentation, so plain-text states are easier to map back.
- **Ask spans on their own:** a `spans` question asked in the same request as other question types can return fewer passages. Send it in its own request for the best recall.
- **Thresholds:** calibrate any decision threshold on `found`, `presence`, or a probability on data from your own use.

## Image Inputs

Send images to the decision model through the same `/decisions/v1/systemone` endpoint used for text decisions. Add an `images` array alongside `model`, `state`, and `questions`. The question types and response format stay the same. Images also enable the [box, boxes, and estimate questions](#typed-answers).

Each image can be a Base64 data URL or an object with `content_type` and `base64` fields. Remote image URLs are not accepted. If an image is hosted online, download it and encode its contents before sending the request.

### Image Requirements

| Requirement | Limit |
|---|---|
| Formats | JPEG (`image/jpeg`), PNG (`image/png`), WebP (`image/webp`) |
| Images per request | Up to 8, or exactly 1 with a `box` or `boxes` question |
| Image size | Up to 5 MB each |
| Request size | Keep the entire JSON body under 4.5 MB, including Base64 image data, state, and questions |
| Total image patches | Up to 10,000 patches of 32 × 32 pixels across all images in a request |
| Aspect ratio | The longer side of each image can be at most 100 times the shorter side |

Base64 encoding increases the request size compared with the original files. Resize or compress images before encoding them if the request is too large, and use the media type that matches each file.


### Image Token Usage

Each image is billed at 1.5 input tokens per 32 × 32 pixel patch, rounded up per image:

```text
patches = ceil(width / 32) × ceil(height / 32)
image_tokens = ceil(patches × 1.5)
```

For example, a 1024 × 1024 image covers 1,024 patches and contributes 1,536 input tokens.

A request is billed its images once, however many questions it asks: two questions about that image still bill 1,536 image tokens, plus the text of each question. These tokens are included in `usage.input_tokens` and charged at the model's input token rate. Every question reads all the images, so image tokens count toward each question's input limit. `usage.output_tokens` remains `0`.

## Audio Inputs

d1.2 and d1.2-ultra also take audio. A clip can be what you ask about, such as a call, a voice message, or a recording to check for a siren. A question can also be a recording, spoken instead of typed.

### Recordings to Decide On

Pass clips in the top-level `media` array. Each clip is an object with `"type": "audio"` and `data`, a 16-bit PCM WAV file as Base64 or as a `data:audio/wav;base64,` URL. The clips come before the state, which can be `null` when the clips are all the model needs. Every question hears every clip, and the answers have the same format as for text.

    ```bash
    {
      "model": "d1.2",
    ```

### Spoken Questions

Any question's `instructions` can be a clip instead of text, in the same `{"type": "audio", "data": ...}` form. The model answers the spoken question like a typed one.

```python
question = base64.b64encode(Path("question.wav").read_bytes()).decode("ascii")

response = requests.post(
    "https://api.liquid.ai/decisions/v1/systemone",
    headers={"Authorization": f"Bearer {os.environ['LIQUID_API_KEY']}"},
    json={
        "model": "d1.2",
        "state": "Order 4417: two lamps, shipped on 12 November, delivered on 14 November.",
        "questions": {
            "delivered": {
                "type": "noul",
                "instructions": {"type": "audio", "data": f"data:audio/wav;base64,{question}"},
            },
        },
    },
)
```

### Audio Requirements

| Requirement | Limit |
|---|---|
| Format | 16-bit PCM WAV, as Base64 or a `data:audio/wav;base64,` URL |
| Clips per request | Up to 8, spoken questions included |
| Total length | Up to 300 seconds of audio per request |
| Request size | Keep the entire JSON body under 4.5 MB, including Base64 audio and image data |

The 4.5 MB request limit usually binds first. Mono audio at 16 kHz fits about 100 seconds in one request. To convert a file with [FFmpeg](https://ffmpeg.org):

```bash
ffmpeg -i call.mp3 -ac 1 -ar 16000 -sample_fmt s16 call.wav
```

<Note>
If a request returns an error saying the model does not accept audio, audio input is not available for that model. Use `d1.2` or `d1.2-ultra`.
</Note>

### Audio Token Usage

Audio is billed by length, at 10 input tokens per second, rounded up per clip:

```text
audio_tokens = ceil(seconds × 10)
```

For example, a 42-second call contributes 420 input tokens. Clips in `media` are billed once per request, like images, and count toward each question's input limit. A spoken question's clip is billed as that question's own text. Audio tokens are charged at the model's input token rate.
