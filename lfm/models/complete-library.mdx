Across the library:

- Context length depends on the model: 32K tokens for most text, vision, audio, and omni models, 256K for LFM3-1.7B, 128K for LFM3-VL-2B, LFM2.5-8B-A1B, d1-2B, and d1-omni-2B, 131K for LFM2.5-24B-A2B, 8K for the LFM2.5 encoders, and 16K for d1-omni-600M. Each model page lists its exact limit.
- Text and vision models run with [Transformers](/deployment/gpu-inference/transformers), [llama.cpp](/deployment/on-device/llama-cpp), [vLLM](/deployment/gpu-inference/vllm), [SGLang](/deployment/gpu-inference/sglang), [MLX](/deployment/on-device/mlx), [Ollama](/deployment/on-device/ollama), and [Atomic Chat](/deployment/on-device/atomic-chat). Audio, omni, retrieval, encoder, and decision models support fewer runtimes (d1-omni-600M: Transformers, llama.cpp, and mlx-vlm); check each model page.
- Most open-weight models can be fine-tuned with [Liquid Finetune](/lfm/fine-tuning/liquid-finetune), [TRL](/lfm/fine-tuning/trl), or [Unsloth](/lfm/fine-tuning/unsloth). The **Trainable?** column in the matrix below lists the documented path for each model.

## Formats

Use the format that matches your runtime and deployment target. The matrix below links the exact repository for each model and format.

- **GGUF** — Best for local CPU/GPU inference on any platform. Use with [llama.cpp](/deployment/on-device/llama-cpp), [LM Studio](/deployment/on-device/lm-studio), [Ollama](/deployment/on-device/ollama), or [Atomic Chat](/deployment/on-device/atomic-chat). Every open-weight model in the matrix has a `LiquidAI/<model>-GGUF` repository.
- **MLX** — Best for Mac users with Apple Silicon. Leverages unified memory for fast inference via [MLX](/deployment/on-device/mlx) or [Atomic Chat](/deployment/on-device/atomic-chat). Many models have official `LiquidAI/<model>-MLX-<bits>` repositories; the others are community conversions on [mlx-community](https://huggingface.co/mlx-community/collections?search=LFM).
- **ONNX** — Best for production deployments and edge devices. Cross-platform with ONNX Runtime across CPUs, GPUs, and accelerators. Available as `LiquidAI/<model>-ONNX` for the LFM3 models and the main LFM2.5 text, vision, and audio models, and for some LFM2 models through [onnx-community](https://huggingface.co/onnx-community); see the matrix.

### Quantization

Quantization reduces model size and speeds up inference with minimal quality loss. Available options by format:

- **GGUF** — Text and vision repositories usually include `Q4_0`, `Q4_K_M`, `Q5_K_M`, `Q6_K`, `Q8_0`, `BF16`, and `F16`. Some repositories ship a smaller set (for example, d1-omni-600M has only `Q8_0`, `BF16`, and `F16`), so check the file list. `Q4_K_M` offers the best balance of size and quality.
- **MLX** — Official LiquidAI repositories usually come in `4bit`, `5bit`, `6bit`, `8bit`, and `bf16`. Some ship a subset (d1-omni-600M has `8bit` and `fp16`). `8bit` is recommended.
- **ONNX** — Supports `FP32`, `FP16`, `Q4`, and `Q8` (some repositories also include `Q4F16`). `Q4` is recommended for most deployments.
