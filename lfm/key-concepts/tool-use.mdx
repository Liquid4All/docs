Tool calling (function calling) lets a compatible model use APIs, databases, and other external services to give accurate, up-to-date answers. The examples cover text, vision, audio, and omni models.

## Overview

The tool use workflow follows four steps:

1. **Define** tools by passing them to [`.apply_chat_template()`](https://huggingface.co/docs/transformers/en/chat_extras#passing-tools) with `tools=...`.
2. **Generate** a response where the model writes each call in its tool call format.
3. **Execute** the function and return results as a `tool` role message.
4. **Regenerate** to let the model interpret results and respond to the user.

## Tool call format

<Tabs>
<Tab title="LFM3">

This format is a superset of `qwen3_coder`. The chat template places tool definitions in the system prompt between `<tools>` and `</tools>`. The model writes each call between `<tool_call>` and `</tool_call>`, with the function name in a `<function=...>` tag and each argument in a `<parameter=...>` tag:

</Tab>
<Tab title="LFM2/LFM2.5">

This format lists tool definitions in the system prompt. The model writes each call between `<|tool_call_start|>` and `<|tool_call_end|>`, as a Pythonic function call by default:

## Text Models

This example runs the full workflow: define the tools, generate a tool call, execute it, and generate the final answer.

<Tabs>
<Tab title="LFM3">

Start by loading the model and defining your tools and conversation:

```python
import json
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "LiquidAI/LFM3-1.7B"
model = AutoModelForCausalLM.from_pretrained(model_id, dtype="bfloat16", device_map="auto", trust_remote_code=True)
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)

tools = [{
    "type": "function",
    "function": {
        "name": "get_candidate_status",
        "description": "Retrieves the current status of a candidate in the recruitment process",
        "parameters": {
            "type": "object",
            "properties": {
                "candidate_id": {
                    "type": "string",
                    "description": "Unique identifier for the candidate",
                }
            },
            "required": ["candidate_id"],
        },
    },
}]

messages = [{"role": "user", "content": "What is the current status of candidate ID 12345?"}]
```

Generate the first response. The model may decide to call a tool:

```python
inputs = tokenizer.apply_chat_template(
    messages,
    tools=tools,
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt"
)

outputs = model.generate(
    **inputs.to(model.device),
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=1024,
)

response = tokenizer.decode(
    outputs[0][len(inputs["input_ids"][0]):],
    skip_special_tokens=False
)
```

After its reasoning, the model outputs a tool call in XML:

<LFM3ToolCallExample></LFM3ToolCallExample>

Parse the tool call and execute the function in your application. Add the parsed assistant call to history as a `tool_calls` entry, then append the result as a `tool` message. `function.arguments` must be a Python mapping, so decode JSON strings with `json.loads()` before applying the template.

```python
# Mock function (replace with actual API call in production)
def get_candidate_status(candidate_id: str):
    return [{
        "candidate_id": candidate_id,
        "status": "Interview Scheduled",
        "position": "Clinical Research Associate",
        "date": "2023-11-20",
    }]

messages.append({
    "role": "assistant",
    "tool_calls": [{
        "type": "function",
        "function": {"name": "get_candidate_status", "arguments": {"candidate_id": "12345"}},
    }],
})
messages.append({"role": "tool", "content": json.dumps(get_candidate_status("12345"))})
```

Generate again, passing the same tool schemas, so the model can interpret the tool result and respond to the user. Keep the assistant's content and reasoning from the current tool-use turn in the history.

```python
inputs = tokenizer.apply_chat_template(
    messages,
    tools=tools,
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt"
)

outputs = model.generate(
    **inputs.to(model.device),
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=1024,
)

final = tokenizer.decode(
    outputs[0][len(inputs["input_ids"][0]):],
    skip_special_tokens=True
)
```

The full conversation now looks like this:

```text
<|startoftext|><|im_start|>system
<tools>
{"name": "get_candidate_status", "description": "Retrieves the current status of a candidate in the recruitment process", "parameters": {...}}
</tools><|im_end|>
<|im_start|>user
What is the current status of candidate ID 12345?<|im_end|>
<|im_start|>assistant
<think>The user wants the status of candidate 12345. I will call get_candidate_status.</think><tool_call>
<function=get_candidate_status>
<parameter=candidate_id>
12345
</parameter>
</function>
</tool_call><|im_end|>

</tool_response><|im_end|>
```

With either model family, you can also pass Python functions with docstrings to `.apply_chat_template()` with `tools=...`. Transformers converts them to JSON schemas:

```python
def get_current_temperature(location: str, unit: str):
    """
    Get the current temperature at a location.

    Args:
        location: The location to get the temperature for, in the format "City, Country"
        unit: The unit to return the temperature in. (choices: ["celsius", "fahrenheit"])
    """
    return 22.

# Apply chat template
inputs = tokenizer.apply_chat_template(
    [{"role": "user", "content": "What's the weather in San Francisco?"}],
    tools=[get_current_temperature],
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt"
)
```

## Vision Models

Vision models can use what they see to choose a tool and fill in its arguments. In this example, the model sees a photo of two cats and routes a request to the most relevant of two tools.

This example shows how to define the tools and generate the tool call. Executing the call and generating the final answer work the same as in [Text Models](#text-models).

Load the vision model as shown in [Vision Capabilities](/lfm/key-concepts/vision-capabilities#setup). This example uses the same image and request for both model families:

![Input image](https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/coco_sample.png)

```python
from transformers.image_utils import load_image

input_image = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/coco_sample.png")
messages = [{
    "role": "user",
    "content": [
        {"type": "image", "image": input_image},
        {"type": "text", "text": "Find a care guide for the animals in this image. Choose the best tool for this request."},
    ],
}]
```

<Tabs>
<Tab title="LFM3">

Pass the tool schemas with `tools=...`:

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "search_pet_care",
            "description": "Search for care guidance for an animal visible in an image.",
            "parameters": {
                "type": "object",
                "properties": {
                    "animal": {"type": "string", "description": "The animal visible in the image"},
                    "topic": {"type": "string", "description": "The care topic to search for"},
                },
                "required": ["animal", "topic"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "search_replacement_remote",
            "description": "Search for replacement remote controls or remote-control accessories visible in an image.",
            "parameters": {
                "type": "object",
                "properties": {
                    "item": {"type": "string", "description": "The remote-control item to search for"},
                    "quantity": {"type": "integer", "description": "How many matching items are visible"},
                },
                "required": ["item"],
            },
        },
    },
]

# Apply chat template
inputs = processor.apply_chat_template(
    messages,
    tools=tools,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

with torch.inference_mode():
    outputs = model.generate(
        **inputs,
        do_sample=True,
        temperature=0.1,
        top_k=50,
        repetition_penalty=1.1,
        max_new_tokens=8192,
    )

text = processor.decode(outputs[0, inputs["input_ids"].shape[1]:], skip_special_tokens=False)
answer = text.partition("</think>")[2].replace("<|im_end|>", "").strip()
print(answer)
```

## Audio and Omni Models

<Info>Spoken tool calls require an audio or omni model with tool-calling support. Load it as shown in [Audio Capabilities](/lfm/key-concepts/audio-capabilities#setup).</Info>

Audio and omni models with tool-calling support can take spoken requests and return tool calls. This example turns one spoken request into two function calls: cancel a streaming-platform subscription at the end of the billing period, then subscribe to a podcast platform's Max plan with monthly billing. StreamBox and PodSpace are fictional services, and the example only prints the proposed calls.

This example shows how to define the tools and generate the tool calls. Executing the calls and generating the final answer work the same as in [Text Models](#text-models).

The example first records the spoken request with [text-to-speech](/lfm/key-concepts/speech-generation#text-to-speech). Define the request, the tools, and the instructions:

```python
import json

tools = [
    {
        "name": "cancel_subscription",
        "description": "Cancel the signed-in user's subscription to a streaming platform at the specified time.",
        "parameters": {
            "type": "object",
            "properties": {
                "platform": {"type": "string", "description": "Name of the streaming platform, for example StreamBox."},
                "effective_when": {
                    "type": "string",
                    "enum": ["immediately", "end_of_billing_period"],
                },
            },
            "required": ["platform", "effective_when"],
        },
    },
    {
        "name": "subscribe_to_podcast_platform",
        "description": "Subscribe the signed-in user to a podcast platform with the chosen plan and billing frequency.",
        "parameters": {
            "type": "object",
            "properties": {
                "platform": {"type": "string", "description": "Name of the podcast platform, for example PodSpace."},
                "plan": {"type": "string", "enum": ["basic", "plus", "max"]},
                "billing_frequency": {"type": "string", "enum": ["monthly", "annual"]},
            },
            "required": ["platform", "plan", "billing_frequency"],
        },
    },
]
instructions = (
    "Return tool calls for both requested actions, in the order requested. "
    "Do not claim that an action has completed without a tool result."
)

tts_messages = [
    {"role": "system", "content": "Perform TTS in British English using a female voice."},
    {"role": "user", "content": "Please cancel my StreamBox subscription starting December first. Then subscribe me to PodSpace on the Max plan, billed monthly."},
]
```

Don't prefill a thinking block for tool calls; the model calls tools without reasoning first.

To get a spoken answer once the tool results are in, start the system prompt with `Respond with function calls, and interleaved text and audio.\n\n`, followed by any instructions and the tool list, and don't pass `suppress_mixed` or `suppress_audio_out`. The model then either calls tools or answers in interleaved text and speech. **Image and speech together**

An omni model can also combine what it sees and hears in one tool call. This example shows the model a restaurant photo and asks by voice to book a table. The model reads the restaurant name from the sign and combines it with the city, date, time, party size, and reservation name from the spoken request. The example only prints the proposed call and doesn't make a reservation.

The example records the spoken request with a booking date one week from today:

```python
from datetime import date, timedelta

booking_date = date.today() + timedelta(days=7)
tts_messages = [
    {"role": "system", "content": "Perform TTS in British English using a male voice."},
    {"role": "user", "content": f"Please book a table for two at this restaurant in Paris on {booking_date:%B %d, %Y} at seven in the evening, under Alex Taylor."},
]

# Apply chat template
inputs = processor.apply_chat_template(
    tts_messages,
    add_generation_prompt=True,
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

torch.manual_seed(0)
with torch.inference_mode():
    outputs = model.generate(
        **inputs,
        max_new_tokens=512,
        generation_mode="audio",
        audio_temperature=0.4,
        audio_repetition_penalty=1.2,
        audio_repetition_window=64,
    )

codes = outputs.audio_codes[:1, :, : outputs.audio_lengths[0]]
with torch.inference_mode():
    speech = codec.decode(codes).audio_values[0].float().cpu().numpy().squeeze()
sf.write("booking.wav", speech, 24_000)
```

## Defer Loading and Tool Search

<Info>Check the model's chat template for deferred tools and `tool_reference` support before using this workflow.</Info>

Every tool definition in `<tools>` is part of the prompt. With a few tools that's fine, but an agent on a phone, in a car, or in a smart home may have hundreds or thousands of tools, far more than fit in the context window.

Models that support this workflow handle large tool catalogs with **deferred tools** and **tool search**:

- **Defer loading:** mark a tool with `"defer_loading": True`. The chat template leaves its definition out of the system prompt, but the tool stays in your `tools` list, so your application still knows its schema.
- **Tool search:** give the model one tool that is always loaded. We recommend naming it `search_tools`. When none of its loaded tools fit a request, the model calls the search tool. Your application runs the search and returns the matching tools as `tool_reference` parts. The chat template adds their definitions to the tool response inside `<additional_tools>`, and the model can call them from then on.

This has two benefits:

- **Shorter prompts:** only the always-loaded tools are in the system prompt. Deferred tools enter the context only when the model needs them.
- **Stable prompt prefix:** discovered tools arrive in the tool response, so the system prompt never changes. Inference engines can keep reusing the cached prefix as the conversation grows.

The workflow:

1. Pass all tools, deferred or not, in `tools` on every request. The chat template raises an error if a `tool_reference` names a tool that isn't in `tools`.
2. In the system prompt, tell the model when to search.
3. When the model calls the search tool, run your search and return a `tool` message with one `tool_reference` part per matching tool.
4. The model calls the discovered tool. Run it and return the result as usual.

When the model calls `search_tools`, return the matching tool names as `tool_reference` content parts. You can put text before them:

```python
messages += [
    {"role": "assistant", "content": "", "tool_calls": [{"id": "call_1", "type": "function",
        "function": {"name": "search_tools", "arguments": {"query": "weather"}}}]},
    {"role": "tool", "tool_call_id": "call_1", "content": [
        {"type": "text", "text": "Found 2 tools."},
        {"type": "tool_reference", "name": "get_weather"},
        {"type": "tool_reference", "name": "get_forecast"},
    ]},
]
inputs = tokenizer.apply_chat_template(messages, tools=tools, add_generation_prompt=True,
                                       return_dict=True, return_tensors="pt")
```

The chat template looks up each referenced name in `tools` and writes the full definitions into an `<additional_tools>` block inside the tool response:

```text
<|im_start|>tool
<tool_response>
Found 2 tools.
<additional_tools>
{"name": "get_weather", "description": "Get the current weather for a city.", "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}
{"name": "get_forecast", "description": "Get a 5-day forecast for a city.", "parameters": {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]}}
</additional_tools>
</tool_response><|im_end|>
```

The model can now call `get_weather` like any other tool, in this turn and in later ones, without searching again.

This example uses a keyword search over a small catalog. In production, replace `search_catalog()` with your own search, for example over tool descriptions with an embedding model.

```python
import json
import re
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "LiquidAI/LFM3-1.7B"
model = AutoModelForCausalLM.from_pretrained(model_id, dtype="bfloat16", device_map="auto", trust_remote_code=True)
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)

def tool(name, description, properties, required, defer_loading=False):
    schema = {
        "type": "function",
        "function": {
            "name": name,
            "description": description,
            "parameters": {"type": "object", "properties": properties, "required": required},
        },
    }
    if defer_loading:
        schema["defer_loading"] = True
    return schema

# The search tool is always loaded; the catalog tools are deferred
tools = [
    tool("search_tools", "Search the tool catalog and return the tools that match a query.",
         {"query": {"type": "string", "description": "What the tool should do"}}, ["query"]),
    tool("get_weather", "Get the current weather for a city.",
         {"city": {"type": "string", "description": "City name"}}, ["city"], defer_loading=True),
    tool("convert_currency", "Convert an amount of money from one currency to another.",
         {"amount": {"type": "number"}, "from_currency": {"type": "string"}, "to_currency": {"type": "string"}},
         ["amount", "from_currency", "to_currency"], defer_loading=True),
]

# Mock functions (replace with actual API calls in production)
functions = {
    "get_weather": lambda city: {"city": city, "condition": "light rain", "temperature_c": 11},
    "convert_currency": lambda amount, from_currency, to_currency: {"amount": round(float(amount) * 1.17, 2), "currency": to_currency},
}

def search_catalog(query):
    words = set(query.lower().split())
    return [
        t["function"]["name"] for t in tools
        if t.get("defer_loading") and words & set(t["function"]["description"].lower().rstrip(".").split())
    ]

def parse_tool_calls(text):
    calls = []
    for name, body in re.findall(r"<function=([^>\n]+)>\n(.*?)</function>", text, re.S):
        arguments = dict(re.findall(r"<parameter=([^>\n]+)>\n(.*?)\n</parameter>", body, re.S))
        calls.append({"name": name, "arguments": arguments})
    return calls

messages = [
    {"role": "system", "content": "You only have one tool right now: search_tools, which searches a catalog of many more tools. If none of your current tools can handle a request, call search_tools to find one, then call the tool it returns."},
    {"role": "user", "content": "Do I need an umbrella in Edinburgh today?"},
]

for _ in range(5):
    inputs = tokenizer.apply_chat_template(
        messages, tools=tools, add_generation_prompt=True, return_dict=True, return_tensors="pt"
    )
    outputs = model.generate(
        **inputs.to(model.device),
        do_sample=True,
        temperature=0.1,
        top_k=50,
        repetition_penalty=1.1,
        max_new_tokens=1024,
    )
    text = tokenizer.decode(outputs[0][len(inputs["input_ids"][0]):], skip_special_tokens=False)
    reasoning, _, answer = text.partition("</think>")
    calls = parse_tool_calls(answer)
    if not calls:
        print(answer.replace("<|im_end|>", "").strip())
        break

    messages.append({
        "role": "assistant",
        "reasoning": reasoning,
        "tool_calls": [{"type": "function", "function": call} for call in calls],
    })
    for call in calls:
        if call["name"] == "search_tools":
            names = search_catalog(call["arguments"]["query"])
            content = [{"type": "text", "text": f"Found {len(names)} tool(s)."}]
            content += [{"type": "tool_reference", "name": name} for name in names]
        else:
            content = json.dumps(functions[call["name"]](**call["arguments"]))
        messages.append({"role": "tool", "content": content})
```

If your search returns full tool definitions instead of names, pass them in the tool message's `additional_tools` field, for example `{"role": "tool", "additional_tools": [weather_schema]}`. The chat template renders them the same way.

Defer loading works with vLLM, SGLang, and compatible llama.cpp builds. For llama.cpp, use a GGUF with the current chat template or load it with `--chat-template-file`.

## Best Practices

Tool definitions consume context tokens since they're inserted as text. For large tool lists (100+ tools), this can use significant portions of your context window.

To manage this effectively, only include tools relevant to the current request. Write clear, concise descriptions. Group related tools and remove unused ones when they're not needed.

Where supported, use [defer loading and tool search](#defer-loading-and-tool-search) for large tool catalogs, so only the tools the model needs enter the context.
