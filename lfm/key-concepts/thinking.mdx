title: "Thinking"
description: "Use LFM thinking models to reason before they answer, separate the reasoning from the final answer, and switch thinking off on models that support it."
---

Thinking models reason before they respond. They write their reasoning into a `<think>…</think>` block at the start of the reply and then give the final answer:

```
<think>15% of 80: 10% is 8 and 5% is 4, so 15% is 12.</think>The answer is 12.
```

This page shows how to run a thinking model on text and on images, how to separate the reasoning from the answer, and how to switch thinking off where a model supports it. The examples use Hugging Face Transformers and OpenAI-compatible servers.

Thinking helps most on tasks with several steps, such as math, logic, documents and charts, planning, and tool use in agents. Every reasoning token is a generated token, so thinking also makes replies longer and slower (see [Leave room for the reasoning](#leave-room-for-the-reasoning)).

## Use thinking

Thinking is on by default for [thinking models](#thinking-models). When you build the prompt with the model's chat template, the template adds the thinking tokens to the start of the assistant turn, so the model reasons before it responds. On models with a thinking switch, this is the same as passing `enable_thinking=True`. See [Chat Template](/lfm/key-concepts/chat-template) for examples of generation prompts.

### Text

<Tabs>
<Tab title="LFM3">

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "LiquidAI/LFM3-1.7B"
model = AutoModelForCausalLM.from_pretrained(model_id, dtype="bfloat16", device_map="auto", trust_remote_code=True)
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)

messages = [{"role": "user", "content": "A shop sells pens at $3 each or 4 for $10. What is the lowest cost for 11 pens?"}]

inputs = tokenizer.apply_chat_template(
    messages,
    add_generation_prompt=True,
    enable_thinking=True,  # the default
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

output_ids = model.generate(
    **inputs,
    do_sample=True,
    temperature=0.1,
    top_k=50,
    repetition_penalty=1.1,
    max_new_tokens=16384,
)
text = tokenizer.decode(output_ids[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

### Images and text

Vision models work the same way through the processor:

```python
import torch
from transformers import AutoModelForImageTextToText, AutoProcessor

model_id = "LiquidAI/LFM3-VL-2B"
model = AutoModelForImageTextToText.from_pretrained(model_id, dtype=torch.bfloat16, device_map="auto", trust_remote_code=True)
processor = AutoProcessor.from_pretrained(model_id, trust_remote_code=True)

messages = [
    {
        "role": "user",
        "content": [
            {"type": "image", "url": "http://images.cocodataset.org/val2017/000000039769.jpg"},
            {"type": "text", "text": "How many cats are in this image?"},
        ],
    }
]

inputs = processor.apply_chat_template(
    messages,
    add_generation_prompt=True,
    enable_thinking=True,  # the default
    tokenize=True,
    return_dict=True,
    return_tensors="pt",
).to(model.device)

with torch.inference_mode():
    output_ids = model.generate(
        **inputs,
        do_sample=True,
        temperature=0.1,
        top_k=50,
        repetition_penalty=1.1,
        max_new_tokens=16384,
    )
text = processor.decode(output_ids[0, inputs["input_ids"].shape[1]:], skip_special_tokens=True)
```

<Note>
MLX-VLM is the exception: `mlx_vlm.generate` turns thinking off unless you pass `--enable-thinking`. Add the flag to use thinking. See [MLX](/deployment/on-device/mlx#lfm3-and-d1-models).
</Note>

### Separate the reasoning from the answer

How the reasoning comes back depends on whether a reasoning parser runs.

**With a parser**, the server splits the output for you. The answer arrives in `message.content` and the reasoning in a separate field, so your application never sees the `<think>` tags. The name of the reasoning field differs between servers and versions, so read both:

```python
message = response.choices[0].message
reasoning = getattr(message, "reasoning_content", None) or getattr(message, "reasoning", None)
print("Reasoning:", reasoning)
print("Answer:", message.content)
```

When you stream the response, the reasoning arrives in the same field of each chunk's `delta`, before the answer arrives in `delta.content`:

```python
stream = client.chat.completions.create(
    model="LiquidAI/LFM3-1.7B",
    messages=[{"role": "user", "content": "What is 17 * 23 - 45?"}],
    stream=True,
)
for chunk in stream:
    if not chunk.choices:
        continue
    delta = chunk.choices[0].delta
    reasoning = getattr(delta, "reasoning_content", None) or getattr(delta, "reasoning", None)
    if reasoning:
        print(reasoning, end="", flush=True)  # show it greyed out or hide it in your UI
    if delta.content:
        print(delta.content, end="", flush=True)
```

**Without a parser** (Transformers, MLX, and servers started without one), the reasoning and the answer arrive as one string. The text contains a closing `</think>` before the answer, so split on it:

```python
def split_reasoning(text):
    reasoning, separator, answer = text.partition("</think>")
    if not separator:
        # No closing tag: generation stopped mid-thought. Raise the token limit.
        return reasoning.replace("<think>", "").strip(), ""
    return reasoning.replace("<think>", "").strip(), answer.strip()

reasoning, answer = split_reasoning(text)
```

### Leave room for the reasoning

The token limit covers the reasoning and the answer together. Reasoning on a hard task can run to thousands of tokens, and if the limit is reached first, the model is cut off mid-thought and never gives an answer.

- **vLLM and llama.cpp:** when you don't set `max_tokens`, generation can run to the end of the context window, so you don't need a limit.
- **Transformers, SGLang and other runtimes:** set the limit yourself, to a generous value such as 16,384 tokens.

If a reply has reasoning but no answer, the limit was too low.

### Structured output and tool calls

The reasoning comes first in every reply, also when you ask for JSON or give the model tools:

- **Structured output:** with a reasoning parser, `response_format` (for example a JSON schema) constrains only the answer. The reasoning before it stays free text, and `message.content` holds just the JSON.
- **Tool calls:** the model reasons first and then calls the tool. With a tool-call parser, the call arrives in `message.tool_calls`, and the reasoning in the reasoning field.

Without a parser, both arrive after `</think>` in the generated text.

### Multi-turn conversations

When you add a reply to the conversation history, send the answer as `content` and the reasoning as `reasoning_content`. The chat template then decides which reasoning stays in the prompt:

- **Earlier turns:** by default, the template removes the reasoning from every assistant turn before the latest user message. This keeps long conversations short.
- **The current turn:** reasoning from turns after the latest user message stays. In an agent, this keeps the model's chain of thought across all the tool calls it makes to answer one request, so keep the reasoning with each tool-call turn.

To keep the reasoning from every earlier turn as well, set `preserve_thinking=True`:

- **Transformers:** `apply_chat_template(..., preserve_thinking=True)`
- **vLLM and SGLang:** `"chat_template_kwargs": {"preserve_thinking": True}` in `extra_body`
- **llama.cpp:** the server keeps earlier reasoning by default (`--reasoning-preserve`). Start it with `--no-reasoning-preserve` to use the template's default instead.

## Switch thinking off

Some thinking models can answer without reasoning; others always think. A model may accept the switch without having been trained to answer without reasoning. Check the [model support table](#thinking-models) before switching thinking off.

<Warning>
We recommend leaving thinking on. With thinking off, a model answers faster but less accurately, especially on math, documents and other multi-step tasks. Test your task both ways before you switch it off.
</Warning>

To switch thinking off, set `enable_thinking=False`. The chat template then fills in an empty `<think></think>` block, so the model starts on the answer straight away. On models that always think, this setting isn't supported.

<Tabs>
  <Tab title="Transformers">
    In the [image example](#images-and-text), pass `enable_thinking=False` to `apply_chat_template()`:

    ```python
    inputs = processor.apply_chat_template(
        messages,
        add_generation_prompt=True,
        enable_thinking=False,
        tokenize=True,
        return_dict=True,
        return_tensors="pt",
    ).to(model.device)
    ```

    The empty `<think></think>` block is part of the prompt, so the generated text is the answer alone. Don't pass it to `split_reasoning()`, which expects a closing `</think>`.
  </Tab>
  <Tab title="vLLM and SGLang">
    Send `enable_thinking` in `chat_template_kwargs` with each request. With the OpenAI client, it goes in `extra_body`:

    ```python
    from openai import OpenAI

    client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")  # SGLang: port 30000

    response = client.chat.completions.create(
        model="LiquidAI/LFM3-VL-2B",
        messages=[
            {
                "role": "user",
                "content": [
                    {"type": "image_url", "image_url": {"url": "http://images.cocodataset.org/val2017/000000039769.jpg"}},
                    {"type": "text", "text": "How many cats are in this image?"},
                ],
            }
        ],
        temperature=0.1,
        extra_body={
            "top_k": 50,
            "repetition_penalty": 1.1,
            "chat_template_kwargs": {"enable_thinking": False},
        },
    )
    print(response.choices[0].message.content)
    ```
  </Tab>
  <Tab title="llama.cpp">
    Start the server with `--reasoning off` to switch thinking off for every request:

    ```bash
    llama serve -hf LiquidAI/LFM3-VL-2B-GGUF:Q4_0 \
      --top-p 1.0 --min-p 0.0 --reasoning off
    ```

    To switch it off for a single request instead, send `chat_template_kwargs`:

    ```python
    from openai import OpenAI

    client = OpenAI(base_url="http://localhost:9931/v1", api_key="not-needed")

    response = client.chat.completions.create(
        model="LiquidAI/LFM3-VL-2B-GGUF:Q4_0",
        messages=[
            {
                "role": "user",
                "content": [
                    {"type": "image_url", "image_url": {"url": "http://images.cocodataset.org/val2017/000000039769.jpg"}},
                    {"type": "text", "text": "How many cats are in this image?"},
                ],
            }
        ],
        extra_body={"chat_template_kwargs": {"enable_thinking": False}},
    )
    print(response.choices[0].message.content)
    ```

    Builds before [ggml-org/llama.cpp#31374](https://github.com/ggml-org/llama.cpp/pull/31374) returned a 500 error when thinking was off and `response_format` was set, so update llama.cpp if you use structured output.
  </Tab>
  <Tab title="MLX">
    `mlx_vlm.generate` keeps thinking off unless you pass `--enable-thinking`, so leave the flag out:


## FAQ

<AccordionGroup>

<Accordion title="Why can't I switch thinking off on every model?">
Models that always think are trained to answer after a reasoning trace. Setting `enable_thinking=False`, starting llama.cpp with `--reasoning off`, or filling in an empty `<think></think>` by hand isn't supported on them, and their answers get worse. Some models accept `enable_thinking=False`, but they weren't trained for this, so we don't recommend switching thinking off on them. If you need answers without reasoning, use a [model that doesn't think](#thinking-models).
</Accordion>

<Accordion title="Can I set a thinking budget or a reasoning effort?">
The thinking models in the [model support table](#thinking-models) have one thinking mode, with no effort levels and no trained thinking budget.

Their chat templates don't read a reasoning-effort value, so options such as llama.cpp's `--reasoning-effort` don't change the output for these models. llama.cpp's `--reasoning-budget N` with `N` greater than 0 cuts the reasoning off after `N` tokens. These models weren't trained for this, so test it on your task before you rely on it.
</Accordion>

<Accordion title="How much accuracy do I lose with thinking off?">
It depends on the model and the task. Each model's Hugging Face model card reports benchmark results with thinking on and off where the model can switch.
</Accordion>

</AccordionGroup>
