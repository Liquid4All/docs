Start with [LFM3-1.7B](/lfm/models/lfm3-1.7b) for general text adaptation. [TRL](https://huggingface.co/docs/trl) provides trainers for supervised fine-tuning, preference optimization, and reinforcement learning. The model architecture, chat template, and dataset format still determine the right recipe.

## Installation

The text smoke test below uses Python 3.12, Transformers 5.23.0, TRL 1.18.1, and PEFT 0.21.3 on a CUDA GPU:

```bash
uv pip install "transformers==5.23.0" "trl==1.18.1" "peft==0.21.3" torch accelerate datasets
```

Review the checkpoint's custom code before enabling `trust_remote_code=True`. Use an isolated environment for this recipe; older notebooks can require different package versions.

## LFM3 text LoRA smoke test

This two-step run checks model loading, tokenization, adapter attachment, gradients, and checkpoint saving. Its two synthetic examples are a setup check, not a useful training dataset or a quality evaluation.

```python
from datasets import Dataset
from peft import LoraConfig
from transformers import AutoModelForCausalLM, AutoTokenizer
from trl import SFTConfig, SFTTrainer

model_id = "LiquidAI/LFM3-1.7B"
model = AutoModelForCausalLM.from_pretrained(
    model_id, trust_remote_code=True, device_map="auto", dtype="bfloat16",
)
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)

dataset = Dataset.from_list([
    {"messages": [
        {"role": "user", "content": "What is the capital of France?"},
        {"role": "assistant", "content": "Paris."},
    ]},
    {"messages": [
        {"role": "user", "content": "What is two plus two?"},
        {"role": "assistant", "content": "Four."},
    ]},
])

trainer = SFTTrainer(
    model=model,
    processing_class=tokenizer,
    train_dataset=dataset,
    peft_config=LoraConfig(
        r=8, lora_alpha=16, target_modules="all-linear", task_type="CAUSAL_LM",
    ),
    args=SFTConfig(
        output_dir="./lfm3-sft", max_steps=2,
        per_device_train_batch_size=1, gradient_accumulation_steps=1,
        learning_rate=2e-4, max_length=256, bf16=True,
        report_to="none", save_strategy="no", logging_steps=1,
    ),
)
trainer.train()
trainer.save_model("./lfm3-sft/adapter")
```

`target_modules="all-linear"` lets PEFT find the model's linear layers. Inspect the attached adapters and trainable parameter count before a long run; names copied from Llama/Qwen recipes do not necessarily exist in LFMs. This recipe saves an adapter, not a merged standalone checkpoint.

## Move from a smoke test to training

- Replace the synthetic rows with a representative [instruction dataset](/lfm/fine-tuning/datasets#instruction-datasets-sft) and freeze a separate evaluation set.
- Choose sequence length, batching, training duration, and learning rate for the task and available memory. Reasoning traces count toward the sequence length.
- Preserve the selected checkpoint's template, tool-call format, and intended reasoning behavior in the training data. LFM3 uses XML tool calls; LFM2/LFM2.5 use their earlier formats.
- Evaluate both task quality and the exported inference path. A finite loss and saved adapter establish that training runs, not that the adaptation is good.

For managed configs, distributed launch, evaluation, and export, see [Liquid Finetune](/lfm/fine-tuning/liquid-finetune). Verify that its current configuration supports the selected checkpoint before launching.

## LFM2.5 and LFM2

Keep older models when a smaller footprint, larger MoE, Japanese specialization, or an established deployment is the reason for choosing them. Use their own chat templates and module names. The text trainer structure above can be adapted, but a successful LFM3 smoke test does not certify every older model or training method.

These notebooks retain their named LFM2/LFM2.5 recipes and environments:

## Vision, audio, omni, and preference training

Multimodal training needs a processor, modality-aware data collator, and a compatible trainer. The text-only smoke test above is not an LFM3-VL, Audio, or Omni training recipe. Start with the selected model's [training path](/lfm/models/complete-library#complete-model-matrix) and upstream examples.

[DPO](https://huggingface.co/docs/trl/dpo_trainer) uses preference pairs rather than SFT conversations; [GRPO](https://huggingface.co/docs/trl/grpo_trainer) additionally needs a verifiable reward and a compatible generation backend. Check architecture support in both the trainer and the rollout engine before reusing an older recipe.
