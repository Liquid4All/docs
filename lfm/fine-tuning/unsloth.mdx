  Use Unsloth for faster training with optimized kernels, reduced memory usage, and built-in quantization support.
</Tip>

The example below fine-tunes LFM2.5-1.2B-Instruct with Unsloth. For comprehensive guides and tutorials, see the [official Unsloth LFM2.5 documentation](https://unsloth.ai/docs/models/tutorials/lfm2.5).

Different training methods require specific dataset formats. See [Datasets](/lfm/fine-tuning/datasets) for format requirements for [SFT](/lfm/fine-tuning/datasets#instruction-datasets-sft) and [GRPO](/lfm/fine-tuning/datasets#prompt-only-datasets-grpo).

## Quick Start

This two-step setup check was run on an H100 with Python 3.12. It verifies that LoRA adapters attach and training saves an adapter; use a real dataset and a longer run for useful adaptation.

```bash
pip install "unsloth==2026.11.7" "unsloth_zoo==2026.11.7" "torch==2.14.0" "transformers==5.17.0" "trl==1.15.0" "peft==0.21.3"
```

```python
from unsloth import FastLanguageModel
from datasets import Dataset
from trl import SFTConfig, SFTTrainer

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="LiquidAI/LFM2.5-1.2B-Instruct",
    max_seq_length=512,
    load_in_4bit=True,
)
model = FastLanguageModel.get_peft_model(
    model,
    r=8,
    target_modules=r".*\.(q_proj|k_proj|v_proj|out_proj|in_proj|w1|w2|w3)$",
    lora_alpha=16,
    use_gradient_checkpointing="unsloth",
    random_state=42,
)
adapter_modules = [name for name, module in model.named_modules() if hasattr(module, "lora_A")]
assert all(any(name.endswith("." + part) for name in adapter_modules) for part in
           ("q_proj", "k_proj", "v_proj", "out_proj", "in_proj", "w1", "w2", "w3"))

rows = [
    [{"role": "user", "content": "What is the capital of France?"},
     {"role": "assistant", "content": "Paris."}],
    [{"role": "user", "content": "What is two plus two?"},
     {"role": "assistant", "content": "Four."}],
]
dataset = Dataset.from_dict({
    "text": [tokenizer.apply_chat_template(messages, tokenize=False) for messages in rows]
})
trainer = SFTTrainer(
    model=model,
    processing_class=tokenizer,
    train_dataset=dataset,
    args=SFTConfig(
        output_dir="lfm25-unsloth",
        max_steps=2,
        max_length=256,
        dataset_text_field="text",
        per_device_train_batch_size=1,
        gradient_accumulation_steps=1,
        learning_rate=2e-4,
        bf16=True,
        report_to="none",
        save_strategy="no",
    ),
)
trainer.train()
trainer.save_model("lfm25-unsloth")
```

LFM2.5 uses `out_proj`, `in_proj`, and `w1`/`w2`/`w3`, rather than Llama's `o_proj` and `gate_proj`/`up_proj`/`down_proj`. The regular expression selects those modules explicitly. The assertion catches changes that would silently leave some of them without adapters.

Import Unsloth before Transformers or TRL. Keep the tested versions together: newer Transformers and TRL releases can exceed Unsloth's supported version range.
