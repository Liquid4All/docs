ShareAI receives a web-page link from Android's share sheet, extracts its article text with Jsoup, and summarizes it locally using **LFM2.5-350M**, Q8_0.

Fetching the article and the first model download require internet access. Article text is processed on-device.

## Environment setup

Use Android Studio with JDK 17, Android SDK 36, NDK `29.0.13113456`, and CMake `3.31.6`. The projects pin Kotlin `2.3.20` and llama.cpp `v0.9.0`.

Clone the complete repository so the app can include `examples/android-common` and its pinned llama.cpp submodule:

```bash
git clone --recurse-submodules https://github.com/Liquid4All/cookbook.git
```

The shared runtime handles model downloads, native inference, cancellation, and cleanup. Keep the app and `android-common` directories together.

## How to run it

1. Open `cookbook/examples/ShareAI` in Android Studio and run it on Android 13+.
2. In your browser, open an article, tap **Share**, and choose **ShareAI**.
3. The app fetches the page, downloads the model if needed (about 380 MB), and streams the summary.
4. Share another link to summarize a new article. Each summary starts with an empty model context.
5. Use **Retry** if fetching the page or preparing the model fails.

Launching ShareAI directly uses the sample Liquid AI blog URL in `MainActivity.kt`.

## Code walkthrough

`MainActivity` handles both the initial `ACTION_SEND` intent and later shares through `onNewIntent(Intent)`. This works across the app's supported Android versions.

`WebScrapingViewModel` fetches the URL off the main thread. It removes scripts, styles, navigation, headers, footers, and sidebars before passing the remaining text to `AIChatViewModel`.

The summarizer selects `Models.small` and a short system prompt:

```kotlin
class AIChatViewModel(application: Application) : TextTaskViewModel(
    application, Models.small,
    "You are a helpful assistant.",
)
```

The app prepends `Summarize in one sentence:` to the article text. The ViewModel cancels and joins a previous request before generating a summary for a new link. It retains the model across rotation, avoids resubmitting the same article on rotation, and resets output for each request. The UI observes the complete output state rather than accumulating token events itself.

## Downloads and lifecycle

The first request downloads the model from Hugging Face. Downloads go to a temporary file; the runtime checks the expected size and SHA-256 before publishing the final GGUF. An interrupted download restarts on the next attempt. A verified cached model works offline.

A ViewModel retains the model across screen rotation. Native calls run in one queue per model instance. Cancellation stops the token loop before cleanup releases the model. A failed request displays an error and allows retry.

## Limitations

Jsoup extracts the returned HTML; it does not execute a site's JavaScript or bypass login requirements. The example uses an 8,192-token context shared by the prompt and generated summary. Very long articles can exceed it. Split or shorten the article before generation when extending this example for long documents. Summaries can omit details; compare important dates and requirements with the original article.
