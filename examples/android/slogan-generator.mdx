SloganApp generates marketing slogans locally with **LFM2.5-1.2B-Instruct**, using the Q5_K_M GGUF. Its interface uses Android Views.

## Environment setup

Use Android Studio with JDK 17, Android SDK 36, NDK `29.0.13113456`, and CMake `3.31.6`. The projects pin Kotlin `2.3.20` and llama.cpp `v0.9.0`.

Clone the complete repository so the app can include `examples/android-common` and its pinned llama.cpp submodule:

```bash
git clone --recurse-submodules https://github.com/Liquid4All/cookbook.git
```

The shared runtime handles model downloads, native inference, cancellation, and cleanup. Keep the app and `android-common` directories together.

## How to run it

1. Open `cookbook/examples/SloganApp` in Android Studio and let Gradle sync.
2. Run the app on an Android 13+ device or emulator. Allow about 850 MB for the model, plus memory for inference.
3. Enter a business description and tap **Generate**. The first request downloads and loads the model.
4. Tap **Stop** to cancel. Enter another description to make a new, independent request.

## Code walkthrough

`SloganViewModel` inherits the shared `TextTaskViewModel`. It selects the checkpoint and the system prompt:

```kotlin
class SloganViewModel(application: Application) : TextTaskViewModel(
    application, Models.text,
    "You are a marketing expert. Suggest engaging and creative slogans based on a business description provided by the user.",
)
```

The Activity obtains the retained ViewModel with `by viewModels()`, observes `generation`, and sends the user's description:

```kotlin
viewModel.generate("Suggest slogans for this business: ${input.text.toString().trim()}")
```

The runtime clears the model context before every request. Earlier businesses and slogans do not enter the next prompt. The Generate/Stop control covers both model preparation and generation, so repeated clicks cannot start duplicate loads.

## Downloads and lifecycle

The first request downloads the model from Hugging Face. Downloads go to a temporary file; the runtime checks the expected size and SHA-256 before publishing the final GGUF. An interrupted download restarts on the next attempt. A verified cached model works offline.

A ViewModel retains the model across screen rotation. Native calls run in one queue per model instance. Cancellation stops the token loop before cleanup releases the model. A failed request displays an error and allows retry.

## Further improvements

Add tone and length controls by including them in each prompt. To use another checkpoint, update its model specification, including its verified size and SHA-256, and test it with the pinned runtime.
